## 1. 先说结论：范围必须砍到"一根钉子"

5 天 7 小时听起来比 5 天长，但跨 5 个夜晚、要留出录制与提交，**实际用于写代码的时间只有约 30–35 人时**（其余是部署、录视频、写文档和缓冲）。因此：

- **只做 Pattern A**（终端 + 文件执行），浏览器（Pattern B）明确不做。
- **只做单 Agent 循环**，不做多 Agent、不做插件生态、不做多租户。
- **所有功能围绕一条演示主线**：*"让 Agent 建 Python 项目 → 装依赖 → 跑程序 → 读结果 → 试图 `rm -rf /` → 被真实拦截 → 宿主机完好 → 审计可导出"*。
- 凡是不能进入这条主线的功能，一律 P2。

**一句话验收**：如果 11-07 晚上还不能把上面这条主线**一遍过地真实跑通并录下来**，就放弃一切加分项，只保主线。

## 8. 单人执行的现实提醒

- **不要并行开三条战线**（前端/后端/部署同时半成品）。按 D1→D4 串行，每天只有一个"必须打通"的点。
- **UI 是时间黑洞**。MVP 用现成组件库（shadcn/ui 或 Ant Design），不写自定义设计系统；时间线用 SSE + 简单列表即可。
- **视频比代码更容易翻车**。11-06 晚的彩排必须计时；11-07 必须录出可用版本。
- **提交截止是北京时间周一早上 6 点**。周日晚上必须完成提交，不要赌"周一凌晨再交"。
- **不要在 11-08 改架构**。任何"顺手重构"都是交付风险。
