### 2.3 外部对照：两个 agent 框架的真实 PR + CI 证据

为避免把合成集当成唯一证据，新增了独立目录 `benchmarks/external/`。样本为
**12 条真实公开 PR**，来自两个独立的 coding-agent 框架账号：

| 来源 | 样本数 | 采集日期 | 证据 |
|---|---:|---|---|
| GitHub Copilot coding agent | 6 | 2026-11-05 | PR head SHA 的 GitHub check-runs |
| OpenHands agent | 6 | 2026-11-05 | PR head SHA 的 GitHub check-runs |

判定规则：`claim` 取 PR 标题/摘要；`should_accept` 仅当至少观测到一个 check，
且没有 `failure` / `cancelled`。因此样本中有 10 条应接受、2 条应拒绝；两条拒绝
都是真实已合并 PR，但 head SHA 上仍有失败/取消的检查。

| 指标 | summary-only | claim–evidence |
|---|---:|---:|
| 应接受用例 | 10 | 10 |
| 应拒绝用例 | 2 | 2 |
| 误接受（FP） | 2 | 0 |
| 误拒绝（FN） | 0 | 0 |
| reject recall | 0.0 | **1.0** |

复现：

```bash
python scripts/claim_evidence_external.py \
  --cases benchmarks/external/cases.json
```

**局限**：这是便利样本，不是随机抽样；CI 通过不等于语义正确；PR 描述可能被
人工编辑；样本量小，不能据此宣称统计显著或普适优势。它只回答“summary-only
是否会把有失败 CI 的真实 agent PR 误判为完成”，不替代独立第三方 benchmark。

## 5. 未覆盖 / 残余风险

1. **任务运行模式**：默认 single 为单写者；multi 已支持多进程 DB claim，但 rate limit / SSE 配额虽已 DB 化，仍需按负载调参。
2. **队列溢出**：超过 `TASK_QUEUE_MAX` 的 queued 任务会等到下一轮周期重试；不会丢，但不是即时。
3. **App 停机期间**：app 侧 reaper 不在线，孤儿容器要等 app 启动后清理。
4. **签名私钥保管**：Ed25519 私钥只在 app VM 一份；丢失后无法为新证据签名，需要离线备份/轮换流程。
5. **保留策略**：默认 `TASK_RETENTION_DAYS=30` 会删除更老的终态任务与 trace；需要长期归档时必须在删除前导出备份。
6. **gVisor**：生产已使用 `runsc`，但宿主无 `/dev/kvm`，走 ptrace platform；内核攻击面显著缩小，但不是零。
7. **策略绕过**：静态规则无法覆盖所有编码/两段式脚本与运行时语义；容器/gVisor 边界是兜底。
8. **沙箱镜像**：生产按 `@sha256` digest 固定；重建镜像后必须同步更新 controller 配置。
9. **证据信任边界**：拥有宿主 root 的攻击者可改 trace/anchor；签名只保护持有私钥之前的完整性。
