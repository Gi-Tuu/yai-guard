## 5. 未覆盖 / 残余风险

1. **任务运行模式**：默认 single 为单写者；multi 已支持多进程 DB claim，但 rate limit / SSE 配额虽已 DB 化，仍需按负载调参。
2. **队列溢出**：超过 `TASK_QUEUE_MAX` 的 queued 任务会等到下一轮周期重试；不会丢，但不是即时。
3. **App 停机期间**：app 侧 reaper 不在线，孤儿容器要等 app 启动后清理。
4. **签名私钥保管**：Ed25519 私钥只在 app VM 一份；丢失后无法为新证据签名，需要离线备份/轮换流程。
5. **保留策略**：默认 `TASK_RETENTION_DAYS=30` 会删除更老的终态任务与 trace；需要长期归档时必须在删除前导出备份。
6. **gVisor**：生产已使用 `runsc`，但宿主无 `/dev/kvm`，走 ptrace platform；内核攻击面显著缩小，但不是零。
7. **策略绕过**：静态规则无法覆盖所有编码/两段式脚本与运行时语义；容器/gVisor 边界是兜底。
8. **沙箱镜像**：生产按 `@sha256` digest 固定；重建镜像后必须同步更新 controller 配置。
9. **证据信任边界**：拥有宿主 root 的攻击者可改 trace/anchor；签名只保护持有私钥之前的完整性。
