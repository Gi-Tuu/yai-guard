## 2. 部署拓扑对比与推荐
### 2.1 两种拓扑

```
A 单 VM                                  B 双 VM（推荐）
Internet──443──► app + Caddy             Internet──443──► yai-app 2c4g（持有全部 key）
                 └ Docker ─► 沙箱容器                     │ VPC 10.99.0.0/24
                   (--network=none)                       ▼
                                              yai-sandbox（唯一执行面，无 LLM key，入站全拒）
```
### 2.2 对比 + 「沙箱与应用进程隔离」怎么满足

| 维度 | 单 VM（容器边界） | 双 VM（网络边界，推荐） |
|---|---|---|
| 5 天 / 30 天 VM 成本 | $7.20 / $40.00（4c8g） | **$7.20 / $40.00**（两台 2c4g）｜KVM $10.80 / $63.20 |
| 执行不在 app 进程内 | 独立 PID/mount/net namespace | app VM 上**没有执行器**，只有 HTTP 客户端 |
| 不读走密钥 | 不挂 env；但同机共享宿主 `/proc` | 沙箱 VM **无任何 API key**，只发 5 分钟单次 task token |
| 不可横向 | `--network=none`，装包靠预构建镜像 | 入站全拒，只许回连 app 的**一个** VPC 私网端口 |
| 资源不越界 | `--cpus --memory --pids-limit` + 只读 rootfs | 同上，或 `msb create --cpus 1 --memory 256M`（硬隔离） |
| 可秒级销毁 / 可审计 | `docker rm -f`；记录容器 id、exit code、stdout | `destroy instance` / `msb remove`；销毁事件本身进审计 = **containment moment 素材** |
| 残余风险 / 故障域 | 逃逸即面对 app（同机）；沙箱 OOM 会拖死反代 | 逃逸只拿到一台无密钥的一次性 VM；沙箱挂 → 首页与审计时间线**仍可访问** |
| 必须做到的硬约束 | 不挂 `docker.sock`、非 root、不共享宿主目录、出站默认关 | Firewall 只管入站 → **egress 必须在沙箱层做**；app→sandbox 用共享 token |

**唯一例外**：11-03 深夜还没跑通网络，先用单 VM 抢上线，11-05 前再拆（拆机 <30 分钟，app 只通过 `SANDBOX_BASE_URL` 访问沙箱）。

### 2.4 反向代理：Caddy（推荐）vs Nginx

选 **Caddy 2**：内置 ACME，域名指过去自动签发续期，省 30–60 分钟且不会半夜证书过期；Nginx 需 certbot + 定时器 + reload，仅作兜底。

```caddyfile
# /opt/yai-guard/deploy/Caddyfile —— 只需改 DOMAIN
{
  email admin@example.com          # 换成真实邮箱，Let's Encrypt 到期提醒
}
{$DOMAIN} {
  encode zstd gzip
  reverse_proxy yai-app:8080 {
    flush_interval -1              # 流式审计输出必须关缓冲
  }
  header Strict-Transport-Security "max-age=31536000; includeSubDomains"
  header X-Content-Type-Options "nosniff"
  header X-Frame-Options "DENY"
}
```

### 2.6 SSH 加固（两台都做；Vultr Ubuntu 默认给 root）

```bash
adduser --disabled-password --gecos "" yai && usermod -aG sudo,docker yai
install -d -m 700 -o yai -g yai /home/yai/.ssh
install -m 600 -o yai -g yai /root/.ssh/authorized_keys /home/yai/.ssh/authorized_keys
sudo tee /etc/ssh/sshd_config.d/99-yai.conf >/dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
AllowUsers yai
MaxAuthTries 3
X11Forwarding no
EOF
sudo sshd -t && sudo systemctl restart ssh
```
> 顺序：**先在 Firewall 把 22 限到我的 IP，再改 sshd**；改完另开终端验证 `ssh yai@<IP>` 能进。锁死只能用网页 Console 救。
### 2.7 开机自启（systemd + compose `restart` 双保险）

```ini
# /etc/systemd/system/yai-guard.service
[Unit]
Description=YAI Guard (docker compose)
Requires=docker.service
After=docker.service network-online.target
Wants=network-online.target
[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/yai-guard
ExecStart=/usr/bin/docker compose -f deploy/compose.yaml up -d --remove-orphans
ExecStop=/usr/bin/docker compose -f deploy/compose.yaml down
TimeoutStartSec=300
[Install]
WantedBy=multi-user.target
```
`sudo systemctl enable --now docker yai-guard.service`；每个 service 同时写 `restart: unless-stopped`。**两层分工**：容器自愈靠 compose，开机顺序靠 systemd（避免 compose 抢跑）。

## 6. 成本控制与「忘记关机」防护
### 6.1 看哪里 / 提醒怎么配
面板：Console → **Billing**（余额/待计费）、**Billing History / Invoices**、**Bandwidth Usage**；资源全量看 Products → Instances / **Block Storage / Snapshots / Object Storage**（四类都要看）。
**官方没有余额阈值提醒**（已核实：通知偏好只有 Outage and Maintenance / Invoices / Bandwidth Usage）→ 自建 cron：
```bash
# /usr/local/bin/yai-budget-check.sh（app VM，每小时）
KEY="${VULTR_API_KEY:?}"; T="${THRESHOLD:-120}"
read -r BAL PENDING < <(curl -s -H "Authorization: Bearer $KEY" https://api.vultr.com/v2/account \
  | jq -r '"\(.account.balance) \(.account.pending_charges)"')
echo "$(date -Is) balance=$BAL pending=$PENDING"
awk -v r="$(awk -v b="$BAL" 'BEGIN{printf "%.2f",200+b}')" -v t="$T" 'BEGIN{exit !(r<t)}' \
  && echo "!! 剩余 < $T，检查忘删资源" >&2
```
`crontab`: `17 * * * * VULTR_API_KEY=xxx /usr/local/bin/yai-budget-check.sh >> /var/log/yai-budget.log 2>&1`。**再加手机闹钟 每天 23:50**（会忘的不是脚本，是人）。
