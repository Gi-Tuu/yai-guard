## 0. 背景

评委只看四样东西：README、5 分钟视频、slides、Demo URL。本单目标：把"我们真的做到了"讲清楚，**不吹没验证的东西**。

## 1. 交付物

| 文件 | 内容 |
|---|---|
| `README.md` | 项目一句话、架构图（Vultr 双 VM）、Quickstart（本地离线 + 部署）、**Containment 证据**、审计说明、非目标、MIT、静态检查 |
| `docs/submission/slides.md` | 10–12 页大纲，每页标题 + 3–5 个 bullet + 建议截图 |

**视频脚本必须包含的时间点**
- 0:00–0:30 问题：Agent 会执行，但爆炸半径不可控
- 0:30–1:10 架构：app VM（密钥）/ sandbox VM（零密钥）/ Vultr Inference
- 1:10–2:30 真实执行：建项目 → 装依赖 → 跑程序 → 读真实输出（无剪辑伪造）
- 2:30–3:40 **containment moment**：`rm -rf /` 被拒 + fork bomb 被 pids 限制 + `curl|sh` 被零网络拦住（至少 2 个）
- 3:40–4:20 宿主完好：`df -i` / 文件数 / 进程数前后对比；trace 校验通过
- 4:20–5:00 价值与边界：谁需要、为什么、什么不做

## 2. 验收

- README 里的每条命令都能照抄跑通（本地离线部分）；部署部分标注"需 Vultr 账号"。
- `wc -c` 检查：标题 ≤50、短描述 ≤255、长描述 ≥100 words。
- 视频脚本计时合计 ≤5:00，且每个 containment 镜头都有"录什么、说什么"。
- 全文搜索这些词，确认没有越界声明：`gVisor enabled`、`KVM`、`100% secure`、`zero risk`、`production-ready`（除非有证据）。

## 3. 写文件范围

`README.md`、`docs/submission/`。**不要改代码**；需要截图找 WO-03，需要证据找 WO-01。

## 4. 禁止

- 不写没验证的能力（例如"支持浏览器自动化""多租户"）。
- 不把"命令过滤"说成安全保证；必须写"容器边界才是兜底"。
- 不使用未经确认的成本/价格数字（引用 `docs/07` 的口径与日期）。
- 不泄露任何 key、真实 IP、账号信息（截图前打码）。

## 5. 接口契约

README 的架构图与 `docs/05` §10 一致；事件/字段名与 `docs/05` §9 一致；如果实现有偏差（JSON 策略、静态 HTML、无 apply_patch），按 `docs/08` §8 如实写。

## 6. 坑

- 5 分钟很短：按"问题 30s / 架构 40s / 执行 80s / 拦截 70s / 证据 40s / 价值 40s"分配，别在架构图上超过 1 分钟。
- 录屏前先彩排计时；卡顿就剪掉等待段（但不要剪掉真实执行的因果链）。
- 封面图 16:9；视频 ≤300MB（导出 1080p H.264 通常够）。
