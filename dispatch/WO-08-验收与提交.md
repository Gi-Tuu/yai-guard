## 0. 背景

最后一关：确认"评审按 README 从零走一遍能复现"，并且提交表单不缺项。本单不写功能，只做**验收与拦截**。

## 1. 交付物

| 文件 | 内容 |
|---|---|
| `scripts/verify_submission.py` | 自动检查：单测、红线、离线 demo、markdown 链接、`.env` 未入库、LICENSE、README 关键小节、视频文件规格（若存在） |
| `docs/qa/acceptance.md` | 人工清单 + 每项结果（PASS/FAIL/阻塞） + 失败项 owner |

**`verify_submission.py` 至少检查**
1. `python -m unittest discover -s backend/tests -t backend` 返回 0
2. `python scripts/check_no_host_exec.py` 返回 0
3. `python backend/demo_offline.py` 返回 0 且输出含 `hash-chain verify = True`
4. 所有 markdown 相对链接存在
5. `git ls-files` 里没有 `.env`、`artifacts/`、`*.key`
6. 存在 `LICENSE` 且含 `MIT`
7. `README.md` 含关键词：`Vultr`、`Containment`、`Quickstart`、`MIT`、`sandbox`
8. 若 `docs/submission/video.mp4` 存在：时长 ≤300s、大小 ≤300MB（用 `ffprobe`，没有就跳过并提示手动检查）

## 2. 验收

```bash
python scripts/verify_submission.py
# 期望：ALL CHECKS PASSED（或列出 FAIL 项与 owner）
```

- [ ] **11-09 03:00 前完成提交**（留 3 小时缓冲）

## 3. 写文件范围

`scripts/verify_submission.py`、`docs/qa/`。不要修别人的代码；发现问题写进 `acceptance.md` 并 @owner。

## 4. 禁止

- 不允许"跳过失败项直接提交"；FAIL 必须记录并给出替代方案。
- 不修改测试来让检查通过。
- 不在提交前做重构/升级依赖。

## 5. 接口契约

依赖各工单的验收命令；如果某命令不存在，说明该工单没交付，直接 FAIL 并指出。

## 6. 坑

- 视频时长用 `ffprobe -v error -show_entries format=duration -of csv=p=0 file` 读，别信文件属性。
- 公网检查要在手机热点/无痕窗口做一次，避免缓存与内网代理假象。
- 提交表单会有字符上限，提前在 `submission-copy.md` 里用 `wc -m` 量好。
